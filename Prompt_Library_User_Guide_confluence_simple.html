1. Purpose

Why this workbook exists

This workbook stores reusable prompts for banking and analytics use cases. Each row represents a single prompt with its persona, required inputs, and expected output — so teams can find and reuse prompts quickly and consistently.

Outcome you want: fewer one-off prompts, faster discovery, and predictable outputs across teams.

2. Sheets

Where to look for what

3. Column definitions (Prompt_Library)

What each field means
ColumnDescription
Sr.No.Unique identifier for the prompt. Keep stable once shared.
Prompt IDUnique prompt identifier for each prompt.
CategoryHigh-level area such as Competitor research, Analytics, ML, HR, IT, etc.
Tags/LabelsComma-separated keywords for search (domain, workflow, tools).
Prompt ObjectiveShort one-line description of what the prompt does.
PromptThe full text given to the LLM, including instructions and context.
Required InputList of inputs needed before running the prompt.

Coworker ReviewReview given by a coworker (1–5) who used the prompt earlier.
SourceSource of the prompt knowledge; generic or written by a team.
Applied ProgramsPrograms or applications involved with the prompt.
Editorial RecommendationsRecommendations from the author.
Speed tip: keep Tags/Labels rich and consistent — it improves prompt discoverability immediately.

4. How to use a prompt

A repeatable workflow
  1. Filter by Category and Tags/Labels to find a relevant row.
  2. Read the Prompt Objective to confirm it matches your task.
  3. Collect items listed in Required Input.
  4. Paste the Prompt into your LLM and fill placeholders like {placeholders}.
  5. If you adapt a prompt, save it as a new entry and update Objective, Required Input, Output Format.

8. Maintenance tips

Keep the library clean and easy to trust
  • Keep wording consistent and avoid overlapping prompts unless clearly versioned.
  • When you change a prompt, update “Last Update Date” and add a short note in “User Feedback”.
  • Use consistent taxonomy for Categories/Tags; assign an owner and a review cadence.

11. Limitations

Teams Copilot + generative reproducibility
  • Edits via Teams Copilot can be inconsistent: content may be rewritten or formatted differently across runs — review changes before committing.
  • Generative outputs aren’t perfectly reproducible: results may vary by model/version/context — store example outputs when consistency matters.
  • Governance in Excel is lightweight: duplicates and taxonomy drift can accumulate — define owners and a review cadence.
